## 目的与可观察结果

在最多四台相机上将 Line 0 固定为断纸光电开关输入，将 Line 1 固定为曝光同步频闪输出。服务启动、连接、配置更新和断线恢复后都维护可查询的事实快照；边沿经有界 latest-wins 邮箱和可停止分发线程到达服务观察者，并通过 `camera.lineInputChanged` 推送到 Qt。控制台顶部显示四路聚合状态，相机页显示当前相机状态、保存值和设备回读值。该信号不写报警历史、不增加报警计数、不触发断纸事件窗口。

完成证据包括 schema v2→v3 迁移与严格校验测试、Mock/伪 MVS/IPC/UI 自动化测试、Debug/Release 构建与 CTest、格式/SDK 边界/diff 检查；实体相机电气与时序验证在核对接线和隔离后由人工执行，未执行前明确标为待硬件验证。

## 前置条件与假设

- 目标 SDK/相机节点采用用户已核对的 MVS V5.0 手册语义：`StrobeLineDuration` 为脉宽、`StrobeLinePreDelay` 为源前延迟、`StrobeLineDelay` 为源后延迟，源固定 `ExposureStartActive`。
- `LineMode=8` 表示 Strobe；伪 SDK 验证 API 调用和节点名，不能证明真实固件、电气电平或微秒时序。
- 两路 I/O 默认关闭；启用前由现场人员核对频闪灯电气规格、接线和隔离。
- 快速边沿允许合并；邮箱最终保存最新原始电平和严格递增修订。

## 设计说明

相机公开层只暴露领域枚举、时间范围、保存/实际参数和 `LineInputEvent`，不暴露 MVS 常量或结构。设备接口提供设置/移除观察者和状态快照；Hikrobot C 回调只判定 Line 0 上升/下降、递增对应槽修订并覆盖槽内容。运行时分发线程唤醒后逐槽取最新项并在 SDK 回调栈之外通知服务。服务按相机配置的有效电平转换 `alarmActive`，同时更新快照与发布 JSON 推送。查询快照包含修订和采样时间，是断线、重连和漏推送后的事实源。

配置读取接受 v2 并在内存补安全默认值，下一次序列化/保存写 v3；v3 严格要求完整 `lineIo`。更新事务继续使用暂停、写入、回读、恢复和失败回滚，事件通知失败、回读失败或不支持均映射稳定 `CAMERA_*` 业务错误，同时保留厂商诊断字段。

### 线程和队列

| 通道 | 生产者 | 消费者 | 容量 | 满载策略 | 停止/排空行为 | 指标 |
| --- | --- | --- | ---: | --- | --- | --- |
| Line 0 输入邮箱 | MVS C 回调（每相机一槽） | 相机 I/O 分发线程 | 4 个槽，每槽 1 项 | `coalesce_latest`，覆盖同相机旧边沿 | 先停事件通知及回调来源，再请求停止、唤醒并 join；不保证交付停机前中间边沿 | 每槽修订、覆盖次数（如现有指标边界允许） |
| IPC 输入状态推送 | 服务观察者 | IPC 客户端 | 复用有界推送队列 | 每相机独立 `coalesce_latest` key | 断线丢弃推送，重连用 `camera.list` 恢复 | 推送修订、时间戳、客户端过期标志 |

### 持久化与恢复

- schema v3 保存完整 `lineIo`；v2 读取补默认关闭和值 0，高有效。
- 配置原子替换、备份、审计和修订冲突沿用现有仓储。
- 设备实际值和输入电平不是配置事实，不持久化；连接/重连后回读纠正。
- 回滚代码前保留 v3 配置副本；旧程序不得猜测 v3。不得删除用户配置和备份。

### 错误和降级

- 不支持 Line 0/Line 1：能力中明确原因，控件禁用；默认关闭配置仍可加载。
- 事件注册/通知/初值读取失败：返回稳定 `CAMERA_*` 错误并附厂商节点/错误码诊断，不启动伪正常状态。
- 频闪写入或回读不一致：回滚上一组已验证参数并恢复采集；回滚失败保留组合错误诊断。
- 断线：停止来源，保留最后状态并标记过期；最后有效态为真时聚合灯保持红色。

## 决策记录

- DEC-001：每相机仅一个 latest-wins 槽，边沿允许合并但由回调侧递增修订并保存最终电平，避免无界事件队列。
- DEC-002：设备输入状态只作为运行时事实源，不持久化；重连由初始 `LineStatus` 纠正。
- DEC-003：Line 0 仅驱动实时状态，明确绕开报警和事件领域。
- DEC-004：v2 读取兼容、v3 保存升级；默认关闭两路 I/O，避免迁移后意外驱动现场线路。
- DEC-005：即使服务尚未安装外部观察者，I/O 分发线程也持续消费容量 1 邮箱并更新运行时快照，确保查询始终是事实源。
- DEC-006：显式设备回读的输入状态时间戳使用 0，真实边沿事件才携带采样时间，避免事务回滚因读取时刻变化而误判不一致。
- DEC-007：同一 IPC 连接代内，低修订的 `camera.list` 响应不得覆盖更高修订推送；跨连接代允许接受从较低修订重新开始的服务快照。

## 意外发现

- 频闪三项范围依赖 `LineSelector=1`，能力探测必须临时选择 Line 1 并恢复原选择器，否则部分设备返回错误范围或不可访问。
- 禁用频闪时安全默认值为 0，因此只在 `strobeOutputEnabled=true` 时执行设备范围约束，避免 v2 安全迁移配置被错误拒绝。
- 客户端自动刷新可能与状态推送交错；加入连接代和修订比较，防止同一连接代的旧查询响应回退最新状态。
- Debug 单元全量首轮中既有 `EventRuntimeNvme.FailedEventPersistenceKeepsLeaseProtected` 用例发生一次观察者时序失败；单独连续复跑 3 次通过，随后 Debug 全量 29/29 通过，未修改该无关模块。
- 仓库全局 `format-check` 被未在本任务修改的 `src/console/main.cpp` 既有格式问题阻断；本任务全部 21 个变更 C++ 文件使用同一 clang-format 执行 `--dry-run --Werror` 均通过。
