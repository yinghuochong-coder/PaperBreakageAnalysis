## 前置条件与假设

- 首期单机最多四路逻辑相机，逻辑 Camera ID 使用 `CAM01`～`CAM04`；
- 工控机可能在网络离线状态生成事件，因此事件 ID 不依赖中心服务；
- 系统墙上时间可能跳变，所有超时和事件窗口必须继续依赖进程内单调时间；
- 上位机协议仍为 DEC-004 未决项，本任务只定义独立版本原则和领域幂等键；
- MVS、Win32、SQLite、Qt/网络原始错误仅作为诊断上下文保留。

## 设计说明

领域模型使用稳定逻辑标识，不把相机 IP、厂商句柄或数据库行号当作业务身份。事件从首次进入 `Candidate` 时取得一个不可变全局 ID；`Confirmed`、`Rejected`、`Timeout` 是同一事件聚合的终态，不创建替代 ID，也不删除审计记录。事件窗口和超时只用单调时间，持久化及交换使用带 UTC 指示的墙上时间。配置修订、配置 schema、协议、事件 schema 和数据库 schema 各有独立计数器与兼容规则。

统一错误由稳定业务码表达机器可判断的失败类别；严重级别、是否可重试和原始错误是错误实例属性。错误码一经发布不能改义或复用，未知原始码也必须映射到最接近的稳定业务码。

### 线程和队列

不适用。本任务只定义领域与错误契约，不新增线程或队列。`PIPELINE_QUEUE_FULL` 只登记有界队列拒绝/丢弃的公共错误语义，具体容量、溢出和关闭行为沿用架构文档并在实现任务中测试。

### 持久化与恢复

本任务不写生产数据。文档将规定：单调时间不得持久化为跨重启可比较时间；事件 ID 和已提交事件 schema 不因恢复改变；配置修订和各 schema 版本独立；数据库迁移版本通过 SQLite `user_version` 管理；已提交事件证据不通过原地升级改写。

### 错误和降级

- 稳定业务码按 `SYS_`、`CAMERA_`、`PIPELINE_`、`ALGORITHM_`、`EVENT_`、`STORAGE_`、`DATABASE_`、`IPC_`、`UPLINK_`、`UPLOAD_` 分类；
- 原始码以 `nativeDomain`、`nativeCode` 和受控上下文保留，不直接对外充当业务码；
- 高频正常背压和超时不用异常控制流；需要对外响应、报警或日志时引用登记码；
- 可重试操作必须由所属模块施加次数/截止时间和退避上限，业务码本身不授权无限重试；
- 敏感信息禁止写入消息和 details。

## 决策记录

- DEC-001：候选、确认、拒绝和超时是同一 `EventAggregate` 的状态；首次进入候选时分配一次事件 ID。
- DEC-002：事件 ID 使用带 `EVT-` 前缀的 UUIDv7 文本；墙上时间只提供大致时序，身份和正确性不依赖时间。
- DEC-003：外部持久化时间统一为 UTC RFC 3339；本地时区只用于展示和可选目录分组。
- DEC-004：将配置内容 schema 与配置修订号分离；所有 schema/协议版本彼此独立。
- DEC-005：业务错误码表达稳定失败类别；严重级别、重试性、原始域/原始码和脱敏上下文属于错误实例。

## 意外发现

- 需求中的 `configVersion` 同时可能指内容格式和配置修订，必须拆分；
