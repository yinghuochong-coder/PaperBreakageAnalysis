## 目的与可观察结果

将 M4-01 的基础托盘扩展为可诊断的四色系统托盘。托盘根据当前连接、服务状态和活动报警映射为绿色、黄色、红色或灰色；菜单可打开控制台或状态页、请求重启 Windows 后台服务、打开由服务返回的事件目录、显示关于信息并只退出 Qt 界面。未到里程碑的预览和诊断包能力必须明确禁用，不伪造执行成功。关闭主窗口仅隐藏，双击托盘恢复窗口，服务断开时托盘为灰色且所有旧状态保留过期标记。

## 范围

### 范围内

- 纯状态模型：连接、服务状态和最高活动报警等级到四色托盘的稳定映射；
- 托盘图标、工具提示、右键菜单、双击打开、主窗口反复显示/隐藏和只退出界面；
- 只读 `system.getLocations` IPC，返回服务已校验并解析的事件根目录；客户端按连接代次同步并标记过期；
- Windows SCM 重启适配器：固定服务名、有限等待、明确权限/状态错误，通过 Qt 事件线程外的受控执行路径调用；
- 状态页、关于、未实现预览/诊断能力的明确菜单反馈；
- 模型、IPC、SCM 和离屏 UI smoke 测试，以及协议/架构/路线图更新。

### 范围外

- M4-03/M4-04 的预览订阅、JPEG、单路或四宫格显示；
- M4-05 的相机状态/配置接口；
- M4-06 的诊断包生成、日志/报警完整页面和导出实现；
- 服务安装策略、UAC 自动提权、安装器或后续里程碑；
- 实体相机、MVS SDK 或生产服务重启实测。

## 当前基线

- Console 主窗口和十二页导航已完成；关闭最后窗口不会退出应用，但主窗口尚未把关闭动作显式转换为隐藏。
- 托盘使用系统电脑图标，仅有禁用状态文本、禁用关于和退出菜单；无颜色模型、双击、窗口/状态导航或服务操作。
- `ClientStateStore` 同步 status/version/metrics/alarms，断线保留旧值并标记 stale；报警摘要尚未保存最高活动等级。
- 服务 IPC 没有路径查询、重启或诊断包命令；有效配置中事件路径已由服务端解析和校验，但相对路径需以配置文件目录求绝对路径。
- SCM 适配器支持安装/卸载所需查询和停止，不支持启动/重启；工作区开始时无未提交修改。

## 前置条件与假设

- Windows 10/11 自带 SCM；目标服务名固定为 `PaperBreakEdgeService`。
- 实际重启需要当前用户具备服务停止/启动权限；本任务不绕过 UAC，权限不足必须显示明确失败，不能声称已重启。
- GUI、托盘和 IPC 仍由 Qt 主线程拥有。重启操作可能等待 SCM 状态变化，因此使用一个有界、可 join 的任务；同一时刻最多一个重启。
- 事件目录由服务端只读接口返回，客户端只允许打开该已同步路径，不接受用户输入路径。
- M4-03 和 M4-06 未完成，因此对应菜单项存在但禁用并注明里程碑。

## 设计说明

- `TrayStatus` 纯模型按优先级映射：连接非 connected 或状态 stale/缺失为灰；服务非 running 或 Error/Critical 活动报警为红；服务 degraded/starting 等异常状态按非 running 归红；Warning 报警为黄；running 且无 Warning 以上报警为绿。旧数据绝不覆盖灰色断线状态。
- 报警摘要解析全部活动报警的最高等级，最近五条仍供页面展示。未知等级使报警数据无效并保持 stale，避免错误映射为正常。
- `system.getLocations` 只接受空对象并返回 `eventRoot` 绝对规范路径；不返回任意客户端输入，也不授予写权限。客户端与其他快照一致按连接代次、有界单请求同步。
- 托盘控制器拥有固定菜单顺序和图标绘制；动作通过回调连接到主窗口、路径打开器和服务重启控制器。双击只显示/激活主窗口。
- SCM 重启封装在平台 Windows 适配器，业务接口不暴露 Win32 类型。操作依次查询、请求停止、在总截止时间内轮询停止、启动并等待 running；错误包含稳定业务码和可选 Win32 原始码。

### 线程和队列

| 通道 | 生产者 | 消费者 | 容量 | 满载策略 | 停止/排空行为 | 指标 |
| --- | --- | --- | ---: | --- | --- | --- |
| 服务重启任务 | Qt 菜单 | 单个 `std::jthread` | 1 | 已有任务时拒绝并提示 | Console 退出请求停止；SCM 轮询每 100 ms 检查 stop token，析构 join | UI 日志记录成功/失败 |

除该单任务外不新增线程或队列；Qt 对象只在 GUI 线程更新，工作结果通过 Qt 排队回调返回。

### 持久化与恢复

不写配置、数据库或事件数据。重启过程不持久化；客户端断线/重连后重新同步所有快照和路径。事件目录只由操作系统资源管理器打开。

### 错误和降级

- IPC 断线/路径同步失败：灰色托盘，状态文本明确过期，打开事件目录不可用。
- SCM 服务不存在、权限不足、停止/启动失败或超时：保持客户端运行并显示稳定错误；不循环重试。
- 无系统托盘：主窗口仍可用，smoke 不将离屏平台的消息能力当作生产托盘证明。
- 预览和诊断包：菜单禁用并标注后续 M4-03/M4-06，不执行占位副作用。

## 验证计划

### 自动化测试

- 托盘状态模型：连接中断/同步中灰色，running 无警报绿色，Warning 黄色，Error/Critical 或服务非运行红色；旧值不得导致断线显示非灰。
- IPC：`system.getLocations` 严格 payload、服务端解析路径和客户端 stale/generation；既有状态同步不退化。
- SCM：单次有界重启的停止、启动、轮询、取消、错误码和超时。
