## 设计说明

采用后台 Windows 服务与 Qt 桌面客户端两个进程。进程 Bootstrap 是依赖装配组合根，`ServiceRuntime` 是注入完成后的生命周期和所有权根；业务核心不依赖 SCM 回调或 Qt Widgets。领域模型使用标准 C++ 类型，平台、厂商、UI 和传输实现通过接口反转。帧使用池化缓冲和只读共享所有权跨通道；所有异步通道有容量、溢出策略、指标和关闭语义。

### 线程和队列

本任务不创建运行时代码，但架构文档必须逐条定义：

| 通道类别 | 约束 |
| --- | --- |
| 帧通道 | 每相机独立、有界、满载丢弃并计数，禁止阻塞采集 |
| 预览通道 | 单槽 latest-wins，无订阅者不编码 |
| 事件通道 | 有界；无法保护/保存时产生 Critical 报警 |
| 控制通道 | 有界；满载返回 busy，不静默丢弃 |
| IPC 推送 | 按消息类别合并或丢弃，可通过查询重新同步 |
| 上传通道 | SQLite 持久化，内存中仅保留有限在途任务 |
| 日志通道 | 有界；采集线程不得因日志阻塞 |

### 持久化与恢复

架构需定义配置原子替换、事件临时目录与最终原子提交、SQLite 版本迁移、NVMe 块校验和启动恢复。本文档本身不引入数据格式。

### 错误和降级

业务错误码稳定，外部/厂商码作为诊断上下文保留。相机、预览、算法、数据库、磁盘和上位机故障不得无条件终止其他独立通道；无法保证事件可靠性时必须显式报警，不得静默成功。
