## 目的与可观察结果

## 当前基线

- `paperbreak_console_model` 仅同步 `system.getStatus`，按连接代次忽略过期响应，并在断线时标记服务状态过期。
- Console 仅创建系统托盘，不创建主窗口；`--smoke-test` 只验证托盘可见。
- 服务已提供只读 `system.getStatus`、`system.getVersion`、`system.getMetrics`、`alarm.list`，以及 `status.changed`、`alarm.raised/cleared` 推送。
- `camera.list` 尚未实现且属于 M4-05，因此相机、检测、上传和上位机数据只能显示明确占位。
- 工作区开始时无未提交修改；Debug 基线构建成功，非硬件 CTest 22/22 通过。

## 前置条件与假设

- Qt 6.10.2 Widgets/Gui/Core 已由现有依赖提供，不新增第三方依赖。
- GUI 和 `ClientStateStore` 均局限于 Qt 主事件线程；本任务不增加工作线程或跨线程队列。
- 动态刷新由一秒 GUI 定时器触发；已有同类请求未完成时跳过，不扩张待响应请求。
- 事件盘空间使用现有 `disk.event.free_gib`；字段缺失或 `available=false` 时显示不可用。

## 设计说明

- `ClientStateSnapshot` 为 status/version/metrics/alarms 分别保存可选值、stale 标记和可选同步错误。断线统一置 stale，但不清空最后值。
- 新连接立即并行同步四类数据。GUI 每秒调用动态刷新，持续请求 metrics 和 active alarms，并在 status/version 仍过期时受控重试。报警推送触发同一受控报警刷新。
- 每类请求最多一个 pending handle。回调必须匹配当前连接 generation 和当前 handle；失败只影响对应数据集。
- 导航定义是固定、只读的十二项描述；Widget 只依赖该模型构建列表和堆栈，默认索引为总览。
- 主窗口顶部显示八项状态；总览只将真实 IPC 数据显示为实时值。未实现的数据明确标注对应后续里程碑。

### 线程和队列

不新增线程或队列。Qt GUI 主线程拥有 Widgets、定时器、`QLocalSocket` 和状态模型；IPC 客户端既有待响应上限 128 保持不变，每类同步请求额外限制为最多一个在途。

### 持久化与恢复

不适用。客户端不写生产配置、SQLite、事件目录或相机。服务重连后按新代次重新查询全部快照。

### 错误和降级

- IPC 断线：顶部显示连接中断，所有远端数据标记“数据已过期”。
- 单项响应无效或失败：保留该项最后值并标记过期/不可用；其他数据不受影响。
- 未实现接口：显示“待 M4-05/M6/M8 接入”，不伪造正常状态或零值。
- UI 退出：停止状态模型、隐藏托盘并关闭日志；后台服务不受影响。

## 决策记录

- DEC-001：严格保留 M4-05 的 `camera.list` 边界，M4-01 相机卡片只显示明确占位。
- DEC-002：复用既有只读命令，不修改服务端协议或配置 schema。
- DEC-003：各数据集独立 stale/error，避免一项失败使整个总览丢失诊断价值。
- DEC-004：报警推送到达时若已有报警查询在途，只记录容量一的刷新意图，当前请求完成后补查一次，避免丢更新或形成无界请求。
- DEC-005：修复由四路并行同步暴露的既有 IPC 出站排水竞态；只在 IPC 事件线程 flush 后安排一次零延迟复核，不改变协议、容量或线程模型。

## 意外发现

- Release 优化构建下，本机服务可在首个响应写空后遗漏预期的后续 `bytesWritten` 排水时机，导致已编码响应滞留在有界出站队列；Debug 时序较慢未稳定复现。通过服务指标确认 handler 已处理、`responses_total` 已增长而 `outbound_messages` 未归零后定位并修复。
