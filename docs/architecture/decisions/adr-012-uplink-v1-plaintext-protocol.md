# ADR-012：Uplink v1 明文无鉴权协议与参考模拟器

- 状态：Accepted
- 日期：2026-08-05
- 修订日期：2026-08-14
- 决策者：项目用户
- 影响里程碑：M8-00～M8-04、R0-01

## 背景

边缘系统需要向上位机发送状态、报警、低帧率预览、事件元数据和大文件，并接收远程命令。此前 REST/WebSocket 端点、认证、TLS 和断点续传契约处于 Deferred，导致 M8 无法形成可重复联调基线。

## 决策

接受 [Uplink v1](../../uplink-protocol-v1.md) 作为正式参考契约：控制与上传使用明文 HTTP，实时消息与 JPEG 预览使用明文 WebSocket，不使用 TLS，不执行应用层鉴权，服务端默认监听全部网卡。请求和消息幂等，大文件按 SHA-256 分块断点上传。`PaperBreakUplinkSimulator` 作为默认构建、独立安装但不进入 PaperBreakEdge 生产包的参考服务端。

边缘端必须按能力协商接受命令。`service.restart` 未声明时稳定返回不支持，不为了该命令强制增加 Windows SCM 路径。现有 edge config v2 的 HTTPS 校验在 M8 边缘适配器接入时统一迁移，本决策不提前修改未接入的边缘配置行为。

## 后果与风险接受

该方案便于隔离现场网络内的部署和联调，但不提供机密性、对端身份、消息来源或传输完整性保证。攻击者可窃听事件和预览、伪造边缘设备、伪造危险命令、重放消息或实施中间人修改；SHA-256 只能发现内容与声明摘要不一致，不能证明摘要来源可信。

项目明确接受上述风险。隔离 VLAN、防火墙/ACL、物理访问控制可以作为现场可选措施，但不再是本项目的功能、部署或发布验收门禁。协议和诊断仍如实说明明文、无鉴权及 SHA-256 的能力边界；本项目不规划 TLS、认证或新的安全协议版本。

## 未选择方案

- TLS + 双向证书：安全性更强，但用户明确选择不纳入本项目路线图。
- Token 或签名鉴权：可限制伪造来源，但用户明确选择不纳入本项目路线图。
- 只提供自动化 Mock：不足以支持长期人工、多设备、故障和断点续传联调。
