## 2. 当前基线

### 2.1 已完成的软件能力

| 原阶段 | 状态 | 当前基线 |
| --- | --- | --- |
| G0～M5 | `completed` | 架构、工具链、服务/IPC、配置、六路相机抽象与采集、Qt Console、预览、候选事件、事件目录和 SQLite 已实现 |
| M6-01～M6-04 | `completed` | 算法插件、传统视觉初版、候选确认/降级和 UI 配置/指标已实现 |
| M6-00 | `blocked` | 缺少经批准的验收数据集、标注和指标；本路线图不自动解除阻塞 |
| M7 | `completed` | PBNVME2 NVMe 滚动缓存、索引/租约和非恢复式 session 缓存已实现 |
| M8 | `completed` | Uplink v1、Mock/参考模拟器、心跳命令、持久上传和分块续传已实现 |
| M9-00 | `completed`（软件与模拟验收） | CAM01～CAM06、配置 schema v7、六路容量基线和 2×3 Console 预览已实现 |

现有实现仍有以下新增差距：

- 帧缺少稳定的校正 UTC、偏移、不确定度、完整同步状态和时钟模型版本；
- 事件不能按外部全局 `eventId + T0` 锁定本机内存/NVMe 缓存；
- manifest/PBNVME 仍为 v3/v2，缺少逐帧严格时间和逐相机实际配置快照；
- Uplink 状态尚未覆盖完整设备、相机和时间同步信息；
- 生产服务尚未把现有 JPEG 预览桥接到远程 WebSocket；
- 事件首次触发通知仍晚于本地窗口获得保护，且外部事件去重不能跨进程恢复。

### 2.2 外部与硬件基线

- 日常自动化测试使用模拟相机、可注入时钟和 Uplink 回环，不依赖实体相机。
- 工控机端交付上限为每机六台 MV-CS020-60GM；多节点自动化场景默认模拟四台工控机。
- Grandmaster、PTP 域、网卡/交换机能力、相机硬件时间戳精度和现场配置由部署环境提供。
- 亚毫秒精度、六台实体相机、正式上位机、生产网络/NVMe、服务强杀和 168 小时稳定性必须分别形成实测记录。
- Uplink v1 保持明文、无应用鉴权；本项目不规划 Uplink v2、TLS 或认证，也不把网络隔离配置作为本路线图验收门禁。

## 3. 范围与执行规则

### 3.1 本路线图范围

- P0：分级时间同步、严格 T0 协同、manifest v4/PBNVME3、配置快照、完整状态和远程预览闭环；
- P1：时钟异常自动恢复、一般报警生命周期和 Critical 报警持久补发；
- 发布收尾：安装升级、诊断闭环、性能/故障注入、168 小时稳定性和发布文档。

### 3.2 范围外

- 上位机业务系统、MySQL 和上位机 UI 的实现；
- Uplink v2、TLS、认证和细粒度远程命令授权；
- PLC 生产协议；
- M6-00 验收数据集制作和无关算法重构；
- 未经单独任务批准的模块边界调整或后续里程碑实现。

### 3.3 任务状态

每个任务只能是：

- `not-started`：尚未领取；
- `in-progress`：已有负责人和独立 ExecPlan；
- `blocked`：存在记录明确的外部阻塞；
- `completed`：满足验收且验证证据已归档。

开始任务前必须阅读需求、系统架构、本路线图、相关源码和 `.agent/PLANS.md`。一个 ExecPlan 只能覆盖一个任务编号，除非用户明确批准合并。

### 3.4 单任务完成门禁

- 只修改任务范围内文件，不自动开始下一任务；
- 行为变更新增或更新模拟/单元/协议测试；
- Debug 构建和非硬件 CTest 通过；发布或格式任务还需 Release 构建；
- 新线程具有停止令牌、截止 join 和确定性关闭顺序；
- 新队列同时定义条数/字节容量、满载策略、指标和报警；
- 相机回调不执行磁盘、网络、JPEG、推理或阻塞等待；
- 新外部输入具有类型、范围、版本、大小和错误语义校验；
- schema、协议、公开行为或架构改变时同步文档、迁移和兼容测试；
- 硬件未执行时明确写“待硬件/系统联调”，不得推断通过。

## 6. T1：时间基础

### T1-01 不可变帧时间模型

- 状态：`not-started`
- 前置：R0-02

扩展帧领域模型，保留原始相机 ticks/频率、接收单调时间和接收 UTC，并增加可空校正 UTC、时钟源、偏移、不确定度、同步状态和模型修订。采集完成后字段不可修改；相机回调只复制已发布的时钟模型并做有界算术。

测试：字段验证、溢出/缺失 ticks、UNSYNCED、模型切换后历史帧不变，以及 Mock/Hikrobot 适配器边界回归。

### T1-02 TimeSyncRuntime 与时钟模型

- 状态：`not-started`
- 前置：T1-01

实现独立工作线程，按“硬件 PTP → OS PTP/NTP → OFFSET_MODEL → RECEIVE_CLOCK”选择来源，发布不可变工控机/相机快照，并提供 UTC↔单调时间映射。模型包含锚点、版本、不确定度和最后错误；旧模型不可回写历史帧。

测试：可注入来源、偏移、漂移、不可用、来源切换、系统时间跳变和关闭超时；本任务只验证 P0 降级，不实现 P1 自动恢复。

### T1-03 生产探针、配置和报警

- 状态：`not-started`
- 前置：T1-02

在 platform 层实现 Windows 时钟探针，在 Hikrobot 适配器内实现相机时间能力/采样；MVS 类型不得越界。配置升级到 schema v8，v7 原子迁移，增加采样周期、不确定度及 Warning/Alarm 阈值。来源变化和阈值持续超限进入状态与报警登记表。

测试：配置迁移/回滚、探针不支持/失败、降级不伪报硬件同步、报警持续时间和确定性关闭。硬件精度保持未验证，直到 V5-02。

### D2-01 PBNVME3 读写与兼容

- 状态：`not-started`

为新事件和严格时间原始块实现 PBNVME3 写入、读取、结构校验、CRC32C、SHA-256 和完整尾标；PBNVME2 解析路径保持独立。写线程、块容量、NVMe 覆盖和事件租约语义不得退化。

测试：黄金文件、损坏隔离、未来版本拒绝、部分写入、取消、PBNVME2 回归和目标 NVMe 待测门禁。

### D2-02 manifest v4、配置快照和 SQLite v7

- 状态：`not-started`
- 前置：D2-01

新事件写 manifest v4，保存 T0、触发来源/节点、各相机实际范围、时间模型版本、整体时间质量、块版本和校验。事件进入 Collecting 前为每个已接受事件预留有界快照工作，实际回读相机配置；不支持字段使用不可用标志，不虚构数值。SQLite schema v7 保存全局映射、时间质量、锁定结果和持久控制 outbox，并提供备份、迁移、回滚和对账。

测试：事件后修改配置不改变历史、读取失败的可解释降级、schema v6→v7 迁移/备份/重启、v3/v4 查询上传兼容。

## 8. E3：严格统一 T0 协同

### E3-01 全局事件 ID、T0 和立即通知

- 状态：`not-started`
- 前置：T1、D2

从确认触发帧的校正 UTC 生成全局 eventId/T0；时间不可用时仍建立降级事件。本地候选窗口获得保护后立即持久化 `BREAK_EVENT_TRIGGERED` outbox，再由 Uplink 控制路径优先发送，不等待后置窗口、JPEG、事件目录或上传。

测试：通知因果顺序、离线补发、相同 eventId 幂等、时间降级、重启恢复和 outbox 容量拒绝；通知失败不得撤销本地事件。

### E3-02 外部 T0 锁定引擎

- 状态：`not-started`
- 前置：E3-01

增加默认容量 64 的高优先级控制通道，满载拒绝最新请求并返回稳定 busy 错误，不使用 drop-oldest。使用创建时的模型把 T0 映射到本机单调时间，为所有启用相机申请内存/NVMe 窗口，形成 COMPLETE/PARTIAL/FAILED 和逐相机实际范围/缺口。

测试：迟到但缓存仍在、过度超前、缓存不足、映射不可用、事件容量满、部分相机失败、序号缺口、P95 内部目标和关闭时取消。

### E3-03 持久幂等与 Uplink 命令

- 状态：`not-started`
- 前置：E3-02

声明 `event.lockByUtc` capability，严格解析命令并返回 `EventLockAck`；未声明时返回 `SYS_NOT_SUPPORTED`。SQLite 按 eventId 保存请求规范值、业务结果和本地事件映射；重启后重放返回原结果，不创建第二目录。来源节点收到自己的广播时返回 duplicate。

测试：同 ID 同内容重放、同 ID 冲突、进程重启、来源节点广播、能力缺失、传统模式和删除生命周期。

## 9. O4：状态、报警与远程预览

### O4-01 完整状态快照

- 状态：`not-started`
- 前置：T1、R0-02

周期状态覆盖 machineId、软件/服务/运行时间、CPU、内存、各数据卷、数据库、Uplink、上传队列和动态六相机数组。相机状态包含身份、实际参数、FPS、丢帧、最后帧和时间同步快照。不支持字段使用 `null + available=false`；超过 1 MiB 时拒绝整条状态并报警，不截断 JSON。

测试：零值与不可用区分、六相机、1 MiB 边界、来源切换、慢状态提供器和旧上位机兼容。

### O4-02 远程预览桥接

- 状态：`not-started`
- 前置：T1、R0-02

扩展 `IUplinkTransport` 二进制预览发送能力，复用 `PreviewRuntime` 已编码 JPEG。远程桥每相机容量 1、最新覆盖，固定工作线程公平轮转，全机默认不超过 5 fps；JPEG 不超过 2 MiB、头不超过 64 KiB。断网、慢消费和丢弃不反压采集、算法、事件或可靠上传。

测试：六相机公平轮转、总速率、覆盖、过大帧、断连/重连、慢消费者、停止取消和本机预览回归。

## 10. V5：P0 集成与验收

### V5-01 模拟器与非硬件 P0 闭环

- 状态：`not-started`
- 前置：全部 P0 软件任务

扩展参考模拟器和集成测试，支持严格/传统混合节点、四工控机广播、乱序/重复 ACK、断网、迟到、重启、缓存不足、状态、预览和 v2/v3/v4 格式兼容场景。验证从收到 `event.lockByUtc` 到完成保护并形成 ACK 的内部 P95 目标不超过 100 ms。

退出门禁：Debug/Release 全量构建、非硬件 CTest、静态分析、格式/协议/黄金文件检查通过；没有重复事件目录或静默丢弃；所有降级原因可解释。

### V5-02 硬件与正式系统联调

- 状态：`not-started`
- 前置：V5-01、目标硬件和正式上位机可用

在目标 Windows 工控机、每机六台目标相机、PTP/Grandmaster、生产等价交换机、目标 NVMe 和正式上位机上验证时钟精度、六路吞吐、广播时延、预览、断链、重启和文件兼容。

未具备环境时任务保持 `blocked` 或 `not-started`，不得用模拟结果替代硬件精度或正式联调结论。

## 11. P1：生产增强

### P1-01 时钟异常检测与自动恢复

- 状态：`not-started`
- 前置：V5-01

检测 PTP/NTP 服务重启、Grandmaster 切换、系统时间跳变和相机 ticks 回绕；模型进入 SYNCING/DEGRADED，重新收敛后提升状态。恢复不得修改历史帧或已创建事件的模型快照。

测试：故障持续、抖动抑制、重复切换、恢复超时、回绕和硬件待测门禁。

### P1-02 报警生命周期与 Critical 持久补发

- 状态：`not-started`
- 前置：V5-01、E3-01 outbox

把一般报警的 raise/update/clear 推送到既有 `alarm` 控制消息；Critical 报警元数据写入有界持久 outbox，断网恢复后补发并保持幂等。报警不得阻塞心跳或可靠事件上传。

测试：去重、更新、清除、断网、重启、容量上限、优先级和非 Critical 不持久化。

## 12. F6：发布收尾

### F6-01 安装、升级和卸载

- 状态：`not-started`
- 前置：P0、P1 软件任务完成

安装服务、Console、运行时和默认配置；支持自动启动、升级保留数据、签名校验、卸载默认保留生产数据和失败回滚。安装器选型先通过 ADR。

### F6-02 健康、报警和诊断闭环

- 状态：`not-started`
- 前置：P1-02

核对系统、相机、算法、存储、数据库、Uplink 和时间同步指标；诊断包包含脱敏配置、日志、健康、报警、软件和依赖版本。输入限界、日志脱敏和依赖清单作为可靠性/发布质量检查，不引入新的 Uplink 安全协议。

### F6-03 性能与故障注入
