### 2.3 硬件与外部依赖假设

- 日常自动化测试使用模拟相机，不依赖实体相机。
- M3 和 G9 的硬件条目必须在安装了 MVS SDK 的目标 Windows 工控机上执行。
- 四路真机、拔网线恢复、磁盘压力、异常断电恢复和 7×24 小时稳定性测试必须保留原始记录；未执行时只能标记“待硬件验证”。
- 生产证书、Token、PLC 和上位机凭据不进入源码库。

## 3. 首期范围和完成定义

### 3.1 首期必须交付

1. Windows 服务可自动启动，未登录桌面时仍可采集。
2. Qt 客户端可独立打开、关闭和自动重连，不影响后台服务。
3. 最多四路相机可配置、绑定、采集、统计和掉线恢复。
4. 预览以 2～5 fps 独立抽样，不能反压高速采集。
5. 模拟或人工触发候选事件后，能冻结并保存配置的前后图像。
6. 事件具备清单、关键帧、校验值、SQLite 索引和崩溃恢复语义。
7. 上位机离线时本地工作不受影响，恢复后可补传。
8. 磁盘水位、服务异常、相机异常和关键队列积压可监测并报警。
9. 在目标工控机上完成四路真机和 7×24 小时稳定性验收。

### 3.2 首期明确不做

- 复杂多机深度学习融合、云端训练、自动训练；
- 完整上位机业务系统；
- 长时间全量原图中心存储或自定义视频编解码器；
- 多用户复杂权限系统；
- Qt 直接控制 PLC 安全停机；
- 工控机之间协同；
- 无人工确认的自动根因结论；
- 在协议未批准前实现具体 PLC 生产适配器。

## 4. 执行与验收规则

### 4.1 任务状态

每个任务只能处于以下状态之一：

- `not-started`：尚未开始；
- `in-progress`：已有负责人和执行计划；
- `blocked`：存在明确外部阻塞，已记录解除条件；
- `completed`：满足任务验收且证据已归档。

路线图默认所有任务为 `not-started`。开始任务时，在对应任务标题后标记状态、负责人、开始日期和 ExecPlan 路径。

### 4.2 单任务完成清单

每个行为或架构变更在标记完成前必须同时满足：

- 只修改任务范围内文件；
- 新增或更新相应测试；
- Debug 构建成功；
- 与发布有关的任务还需 Release 构建成功；
- 相关 CTest 通过；
- 编译警告按错误处理；
- 新增跨线程队列已记录容量、溢出策略和关闭行为；
- 新增线程具有停止令牌、最长等待时间和确定性 join 路径；
- 新增外部输入具有类型、范围和依赖校验；
- 公开行为、文件格式或模块边界变更已同步文档；
- 最终记录执行命令、结果、未执行项和限制；
- 涉及硬件时明确区分模拟验证与真机验证。

### 4.3 推荐验证命令

工程骨架建立后，常规任务至少运行：

```powershell
cmake --preset windows-vs2026-debug
cmake --build --preset windows-vs2026-debug
ctest --preset windows-vs2026-debug
```

发布或部署任务还需运行：

```powershell
cmake --preset windows-vs2026-release
cmake --build --preset windows-vs2026-release
ctest --preset windows-vs2026-release
```

具体任务可以增加筛选测试、静态分析、故障注入和性能测试，但不得用较小测试集替代该任务约定的验收集。

### 4.4 阶段门禁

```text
G0 规划与架构基线
 ↓
M0 工程骨架
 ↓
M1 服务与 IPC
 ↓
M2 相机抽象与模拟器
 ├──────────────┐
 ↓              ↓
M3 真机适配     M4 客户端功能（先用模拟相机）
 └──────┬───────┘
        ↓
M5 内存缓存与完整事件链
        ↓
M6 正式算法接口与初版算法
        ↓
M7 NVMe 滚动缓存
        ↓

        ↓

```

M3 和 M4 可在 M2 完成后并行，但进入 M5 系统联调前必须分别通过各自阶段门禁。

## 7. M1：Windows 服务、配置基础与 IPC

目标：完成独立后台进程、可靠配置和本机控制通道。

### M1-01 服务核心生命周期

实施：

- 将可测试的 `ServiceRuntime` 与 SCM 宿主分离；
- 实现 `--console`、`--validate-config`；
- 实现启动、停止、系统关机处理和有界停止超时；
- 按规定顺序停止接收配置、采集/处理、事件、上传、IPC 和日志；
- 启动失败返回稳定业务错误并记录阶段。

测试：重复启停、启动中取消、部分组件启动失败回滚、停止超时、异常不穿越 Win32 回调。

### M1-02 Windows SCM 集成

实施：

- 实现 `--install`、`--uninstall`；
- 上报 START_PENDING、RUNNING、STOP_PENDING、STOPPED；
- 配置自动启动和异常恢复策略；
- 服务进程不创建界面；
- 安装/卸载要求管理员权限并具备幂等结果。

验证：在隔离 Windows 测试机执行安装、重启、未登录启动、停止和恢复测试；自动化单测只覆盖封装层。

### M1-03 配置模型、校验和原子存储

实施：

- 建立版本化 JSON schema 和强类型配置模型；
- 覆盖系统、相机、采集、预览、算法、事件、存储、上位机、PLC/IO、日志、健康参数；
- 校验类型、范围、跨字段依赖和路径；
- 采用同目录临时文件、flush 和原子替换；
- 保留有限历史版本，支持失败回滚；
- 区分立即生效与重启生效；
- 记录修改来源、版本、时间和脱敏审计数据；
- 不在普通 JSON 保存密码、Token 和私钥。

测试：合法/非法边界、中文和空格路径、截断文件、临时文件残留、版本冲突、写入失败、应用失败回滚。

### M1-04 IPC 帧协议和服务端

实施：

- 基于 QLocalServer/QLocalSocket 实现仅本机 IPC；
- 使用固定字节序长度前缀、JSON 头和可选二进制负载；
- 设置单消息上限、连接数上限、读取超时和积压上限；
- 实现协议版本、requestId、请求/响应/推送关联；
- 先实现 `system.getStatus`、`system.getVersion`、`system.reloadConfig`；
- 对畸形长度、无效 JSON、未知命令和协议不兼容返回稳定错误；
- 配置本机访问权限。

测试：拆包/粘包、零长度、超大长度、随机字节、慢客户端、重复 requestId、断线期间推送、服务停止。

### M1-05 Qt IPC 客户端与重连

实施：

- 提供连接状态模型；
- 使用带抖动的有上限退避重连；
- 请求具备超时、取消和连接代次，旧响应不能污染新连接；
- 客户端断开时明确清除或标记状态为过期；
- 客户端退出只关闭 IPC，不停止服务。

测试：服务先启动/后启动、服务重启、客户端反复开关、请求中断、过期响应。

### M1-06 健康、报警和近期日志基础

实施：

- 建立线程安全的指标快照、报警登记表和状态推送接口；
- 报警包含 code、severity、source、首次/最近时间、active、次数、消息、details 和 acknowledged；
- 支持报警 raise、重复合并、clear 和 acknowledge；
- 提供服务运行时间、CPU、内存、线程、句柄、磁盘、数据库和 IPC 基础指标；
- 实现 `system.getMetrics`、`alarm.list`、`alarm.acknowledge`、`log.tail`；
- 采样和日志查询使用有界结果，慢客户端不得阻塞监测生产者；
- 后续阶段只注册各自相机、算法、存储和上位机指标/报警，不另建平行状态源。

测试：重复报警计数、清除后再发生、确认权限、并发读写、历史结果上限、服务停止时监测线程退出。

退出门禁 M1：

- 界面退出后服务继续运行；
- 服务重启后界面自动重连；
- 非法 IPC 输入和慢客户端不会拖垮服务；
- 配置可验证、原子保存、回滚和审计；
- SCM 真机验证结果已归档，或明确标记待目标机验证。

## 8. M2：相机抽象、模拟器与采集管线

目标：在无厂商 SDK 和实体相机条件下跑通四路采集、状态、队列和故障恢复。

### M2-01 相机接口和领域模型

实施：

- 定义 `ICameraProvider`、`ICameraDevice`、能力描述、参数快照和业务错误；
- 定义 `FramePacket`、`FrameBuffer`、`FrameView`、PixelFormat；
- 帧同时携带相机帧号、服务序号、单调时间和墙上时间；
- 禁止业务接口暴露 MVS 类型、句柄和错误码。

测试：不同能力、参数不支持、设备缺失和重复序列号。

### M2-02 相机状态机与重连控制器

实现 Disabled、Disconnected、Connecting、Connected、Starting、Streaming、Recovering、Faulted；非法转换必须被拒绝并记录。

测试：

- 全状态转换表；
- 1、2、5、10、30、60 秒退避和成功后重置；
- 停止期间取消重连；
- 最大恢复次数后进入 Faulted；
- 多相机状态互不影响。

### M2-03 固定容量帧池和有界队列

实施：

- 预分配固定容量 FrameBuffer 对象池；
- 采集队列显式配置容量；
- 定义 `drop-newest`、`drop-oldest` 或跳帧策略及指标；
- 获取帧、填元数据、入队是采集路径的唯一职责；
- 队列等待可取消、有超时，关闭后生产者和消费者都能退出；
- 禁止采集路径做磁盘、网络、JPEG 或推理。

测试：池耗尽、队列满、消费者停止、生产者停止、并发关闭、无持续分配增长。

### M2-04 模拟相机和故障注入

实施：

- 支持 1～4 路、分辨率、帧率、像素格式和图案配置；
- 支持连续、软触发和模拟硬触发；
- 注入掉线、超时、丢帧、不完整帧、帧号跳变、尺寸/像素格式变化；
- 采用确定性随机种子，测试可重现；
- 提供命令行或测试 API 控制故障。

### M2-05 采集统计与处理骨架

实施：

- 统计实际帧率、丢帧、超时、带宽、最后帧时间和队列深度；
- 创建可配置预处理节点链，首批只做透传、灰度统计、有效性检查；
- 处理线程池可停止，算法积压时按已记录策略跳帧；
- 指标读取不能阻塞采集。

退出门禁 M2：

- 四路模拟相机可稳定运行；
- 能复现并验证掉线、超时、丢帧和重连；
- 所有队列都有容量、溢出指标和停止测试；
- 自动化测试不需要 MVS SDK 或真实相机。

## 11. M5：内存缓存与可靠事件链

目标：先用模拟检测器完成候选生成、前后冻结、可靠落盘、索引和恢复的闭环。

### M5-01 每路内存环形缓存

实施：

- 固定容量对象池，按时长/帧数换算并校验内存预算；
- 正常覆盖最旧帧；
- 事件触发后通过受控引用或所有权转移保护窗口；
- 输出实际缓存秒数、占用和不足报警；
- 多个事件重叠时共享帧，容量不得无界增长。

测试：回绕、精确边界、池耗尽、多个重叠窗口、不同帧率、关闭时仍有事件引用。

### M5-02 模拟检测器和人工触发

实现手动、固定周期、灰度变化和 ROI 占比触发；人工事件写入 `triggerSource=ManualTest`。检测器只依赖算法接口，不依赖相机实现。

### M5-03 候选事件状态机

实现 Idle、Suspicious、Candidate、Confirmed、Rejected、Timeout；Candidate 产生时立即分配事件 ID、记录触发时间/帧、保护前缓存、收集后帧并发通知。

测试：状态转换、连续帧阈值、超时、拒绝、并发相机触发、重复触发幂等和服务停止。

### M5-04 前后窗口冻结和事件合并

实施：

- 按单调时间定位 `[T-pre, T+post]`；
- 墙上时间用于展示和目录命名；
- 限制 `maxEventSeconds`；
- 在 `mergeGapSeconds` 内合并重叠事件；
- 冻结只保护数据，不暂停采集；
- 缓存不足时保留可用范围并产生明确告警/清单标记。

测试：触发帧 N、首尾边界、时间跳变、窗口重叠、跨相机和缓存不足。

### M5-05 关键帧与 JPEG

选择正常参考、最早异常、触发、最大变化、最高置信、确认和事后帧；每个关键帧可追溯到相机、帧号、时间和选择原因。JPEG 在独立工作线程生成。

### M5-06 事务式事件目录和 manifest

实施：

- 使用同卷临时目录写入；
- 原始帧、关键帧和元数据完成后计算校验；
- 最后生成 manifest 并原子重命名；
- 写入任务队列有容量，满时产生 Critical 报警；
- 启动扫描未完成目录，恢复或明确标损；
- 正式目录提交前不能被读取/上传。

测试：各写入点故障注入、磁盘满、权限拒绝、校验不匹配、进程中断残留、中文路径。

### M5-07 SQLite 元数据和迁移

实施：

- 建立 events、event_cameras、key_frames、event_files、upload_jobs、device_status_history、config_history、alarm_history、audit_logs；
- SQLite 只存元数据；
- 从 schema 版本 1 开始提供迁移和回滚/备份策略；
- 事件提交与数据库索引失败之间有可恢复对账流程；
- 支持分页和按时间、状态、相机筛选。

测试：新建、迁移、重复迁移、损坏检测、备份恢复、目录/数据库不一致对账。

### M5-08 存储水位和保留策略

实施：

- warning、critical、stop 水位；
- 优先清理已上传且可删除的最旧事件；
- 默认不删未上传或人工锁定事件；
- 先更新删除状态，再执行可恢复删除/对账；
- 清理临时文件，支持天数和容量上限；
- stop 水位禁止新增大文件但服务仍持续监测报警。

### M5-09 事件配置、查询、复核与导出

实施：

- 实现 `event.list/get/manualTrigger/confirm/reject` IPC 命令；
- 事件配置页支持前/后秒数、最大时长、合并间隔、关键帧数、原始数据、预览视频、上传和保留策略；
- 事件页支持分页、时间/状态/相机筛选、状态、触发相机、置信度、上传状态和缩略图；
- 支持打开已提交事件目录、查看 manifest、确认/误报标记和导出；
- 导出只读取已原子提交的事件，并验证 manifest 与文件校验；
- 提供测试用事件检查器或等价集成测试，能按 manifest 顺序读取原始帧并追溯关键帧；
- `retryUpload` 在 M8 上传队列完成后启用，M5 阶段明确显示尚不可用，不伪造成功。

测试：分页边界、筛选、并发状态更新、未提交目录不可见、损坏事件提示、导出中途失败和中文目标路径。

退出门禁 M5：

- 给定触发帧 N，可验证前后窗口、序列连续性和关键帧来源；
- 人工触发不会停止采集，重叠事件按策略合并；
- manifest 校验正确，未完成事件可恢复或标损；
- SQLite 可查询且迁移测试通过；
- 事件可查询、复核、校验、导出并按帧顺序检查；
- 磁盘满和写入失败不会导致采集线程执行 I/O 或无限阻塞。

## 12. M6：正式算法接口与初版算法

目标：在不改变采集和事件模块的情况下替换检测实现，并让异常可隔离、性能可观测。

### M6-00 算法验收基线

在编码前确定：

- 已标注验证数据集和版本；
- 纸幅/断纸类别定义；
- 准确率、召回率、误报率或业务批准指标；
- 单帧耗时、吞吐和硬件预算；
- 算法模型文件来源、版本和校验方式。

无上述基线时可以实现接口和传统视觉原型，但不能宣称正式算法通过验收。

### M6-01 插件接口与生命周期

实现 `IBreakDetector`、DetectorConfig、DetectionResult、DetectorInfo；支持初始化、处理、热更新、重置和版本查询；插件 ABI/装载策略通过 ADR 明确，第一版可优先采用进程内编译期插件边界。

测试：加载失败、初始化失败、配置回滚、处理异常、超时/慢处理和重置。

### M6-02 传统视觉算法初版

实现经批准的 ROI、灰度/变化量、纸幅占比或背景比较算法；结果至少包含异常、类型、置信、区域、面积比例、变化量、耗时、版本、原因和调试指标。

### M6-03 候选确认和降级

实施：

- 连续帧、阈值、冷却和外部信号组合；
- 算法队列积压时显式跳帧并计数；
- 单次算法异常不退出采集服务；
- 连续异常触发报警并切换到批准的降级状态；
- 配置失败保留旧实例/旧配置。

### M6-04 UI 配置和结果叠加

实现算法启用、类型、ROI、阈值、连续帧、冷却、模型、版本、设备和调试可视化；支持测试当前图像，并展示实际应用状态和性能指标。

退出门禁 M6：

- 模拟检测器和初版算法可替换而不改采集/事件代码；
- 故障、积压和配置失败均有降级与指标；
- 在冻结数据集上生成可复现评估报告；
- 未满足 M6-00 指标时保持“原型”标记。

## 13. M7：NVMe 滚动缓存

目标：提供固定容量、可恢复、不会阻塞采集的磁盘滚动缓存。

### M7-01 格式和容量设计

定义版本化块头、帧索引、原始帧区和 CRC/Hash；确定 1 秒或 5 秒块大小、预分配/写入策略、容量公式和磁盘带宽预算。不自定义复杂视频编码。

### M7-02 异步块写入

实施：

- 独立有界写入队列和线程；
- 写入限速、超时和错误传播；
- 总容量固定，正常删除最旧未保护块；
- 缓存盘不可用时降级内存缓存；
- critical 水位停止普通滚动缓存但保留正式事件能力。

### M7-03 索引、保护和事件引用

按相机和时间定位块；事件窗口通过引用/租约保护相关块；事件提交后按策略释放；跨块帧序列和校验可追溯。

### M7-04 崩溃与断电恢复

启动时扫描块头、索引和校验，截断/隔离不完整块，重建索引；恢复过程有时间和内存上限，不覆盖仍被事件引用的块。

测试：每个写入阶段中断、尾块损坏、索引丢失、校验错误、磁盘移除、容量回绕、事件保护竞争。

退出门禁 M7：

- 缓存占用不超过配置上限；
- 正常块循环覆盖，事件块不被覆盖；
- 磁盘故障不阻塞采集并能降级；
- 故障注入证明残留块可恢复或隔离；
- 目标 NVMe 上持续写入时采集统计满足预算。

## 14. M8：上位机通信与离线补传

目标：在上位机离线时不影响本地检测，恢复后可靠、幂等地补传。

### M8-00 协议评审门禁

在具体协议实现前确认：

- REST/WebSocket 端点、认证、TLS 和证书轮换；
- 消息 schema、版本兼容、幂等键和服务端确认语义；
- 文件分块、断点状态、校验和重试规则；
- 预览是否需要跨机上传；
- 带宽限制和上传优先级；
- PLC 是否进入本阶段以及采用何种协议。

### M8-01 传输抽象和 Mock

实现 `IUplinkTransport` 和 `MockUplinkTransport`；业务层不依赖 HTTP/WebSocket 类型。Mock 可脚本化模拟离线、慢速、失败、重复确认和校验错误。

### M8-02 心跳、状态和命令

实现连接状态、心跳、指数退避、服务端命令处理、协议版本和重复命令幂等；外部命令必须复用服务端校验和审计。

### M8-03 持久化上传调度

实施：

- upload_jobs 使用 SQLite；
- 优先级为报警元数据、关键帧、manifest、低码率回放、原始文件；
- 队列有容量和磁盘上限；
- 指数退避带抖动和最大间隔；
- 重启后恢复任务，不重复创建事件；
- 失败分类为可重试、永久失败和需人工处理。

### M8-04 分块上传与校验

实现文件分块、断点续传、客户端/服务端校验、确认后状态提交；重复块和重复完成请求必须幂等；限速不能占满采集所需网络/磁盘资源。

### M8-05 PLC/现场 IO 抽象（首期预留）

定义 `IPlantIoAdapter`、PlantSignals、VisionAlarm 和 Mock；明确现场安全停机不能只依赖上位机。只有 DEC-005 已决且另行批准时才实现具体协议。

退出门禁 M8：

- Mock 断网期间事件持续保存且上传任务持久化；
- 恢复后按优先级补传；
- 服务/客户端重复请求不产生重复事件；
- 校验失败可重传且有上限；
- 真实上位机协议未提供时，明确保持“Mock 联调完成、生产联调待完成”。

## 15. M9：安全、部署、稳定性与最终验收

目标：把功能工程转为可部署、可维护、可证明满足首期定义的产品。

### M9-01 安装、升级和卸载

实施：

- 安装服务、Qt 客户端、运行时依赖和默认配置；
- 创建专用低权限服务账户与最小目录/网络权限；
- 配置自动启动和异常恢复；
- 数据、日志、缓存和事件目录可配置且升级时保留；
- 升级包签名校验；
- 卸载默认不删除生产数据；
- 安装失败可回滚。

测试：干净 Windows 10/11 x64、覆盖升级、失败回滚、卸载保留数据、非管理员拒绝。

### M9-02 安全加固

实施：

- IPC 仅本机且配置 ACL；
- 生产参数修改需要批准的管理员/应用鉴权；
- TLS、证书和密钥安全存储；
- 日志、诊断包和审计脱敏；
- 外部 JSON、IPC、网络和文件输入做大小/类型/范围校验；
- 依赖漏洞和许可证扫描。

### M9-03 健康、报警和诊断闭环

核对系统、相机、算法、存储、数据库、上位机全部指标；验证报警 raise、去重、计数、clear、ack 和历史查询；诊断包包含脱敏配置、日志、系统/相机/网络/数据库健康、报警、软件和依赖版本。

### M9-04 性能与故障注入

在目标机按固定测试配置记录：

- 四路目标相机的帧率、丢帧、带宽；
- CPU、内存、线程、句柄和所有队列深度；
- 预览开/关、事件写入、NVMe 滚动写入和上传并发场景；
- 相机掉线、上位机断网、磁盘满/移除、数据库异常、系统时间跳变；
- 服务和 Qt 进程分别崩溃后的恢复；
- 事件触发帧 N 的前后窗口和校验。

### M9-05 7×24 小时稳定性测试

要求：

- 目标工控机、四路真实目标相机和生产等价网络；
- 至少连续 168 小时；
- 周期性模拟事件、预览订阅、上位机断连和相机短时掉线；
- 记录内存/句柄趋势、重连、丢帧、队列高水位、事件和校验；
- 中途失败后修复必须重新开始完整计时，除非验收方书面批准缩减复测范围。

通过条件：无持续内存/句柄增长，无未解释服务退出，无丢失的已确认事件，所有丢帧可统计，恢复行为满足约定。

## 19. 后续逐条执行方法

领取任务时使用任务编号，例如“执行 M1-04”。执行者应：

1. 阅读需求文档、本路线图、架构文档和相关源码；
2. 若任务复杂，复制 `.agent/PLANS.md` 中模板创建 `.agent/plans/<task-id>-<slug>.md`；
3. 只实现该编号范围，不自动进入下一个任务；
4. 在 ExecPlan 中持续更新进度、决策、意外发现和验证证据；
5. 完成后回写本路线图任务状态；
6. 最终说明修改文件、验证命令、结果、硬件验证状态和剩余限制。

如果某任务发现必须改变模块边界，应先更新并评审 `docs/architecture/system-architecture.md`；如果改变公开需求，应先更新需求和本追踪矩阵。
