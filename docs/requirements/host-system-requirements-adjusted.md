## 2. 建设目标与系统边界

上位机是多工控机系统的中心管理、事件协调、可靠接收、集中存储和事故分析节点，必须实现：

1. 发现、展示和管理多个工控机及其动态上报的相机；
2. 监控各节点时钟来源、偏移、不确定度和同步状态，但不固定承担 PTP Grandmaster；
3. 接收触发工控机产生的全局 `eventId + T0`，广播到其他节点并汇总锁定结果；
4. 接收 manifest、关键帧和 PBNVME 原始块，建立集中索引和 MySQL 元数据；
5. 提供多相机统一时间轴、逐帧联动、异常定位和可选 OpenCV 后处理；
6. 在工控机、网络、MySQL 或上位机进程异常时保持数据可恢复和状态可解释；
7. 兼容仅支持当前 Uplink v1 的传统节点，并明确展示其能力限制。

### 2.1 系统角色

* **上位机**：设备与时间质量监控、全局事件协调、Uplink 服务端、文件接收、MySQL、后处理和分析 UI。

* **工控机**：相机 SDK 边界、连续采集、算法检测、滚动缓存、事件冻结、本地可靠保存和离线补传。

* **工业相机**：按工控机配置采集并在硬件支持时提供帧号和硬件时间戳。

* **现场时钟基础设施**：可选外部 PTP Grandmaster、支持 PTP 的交换机/网卡或 NTP 服务。

`上位机 -> 工控机 -> 相机` 是唯一远程控制路径。上位机不得直接调用 Hikrobot MVS SDK，也不得依赖工控机本地 SQLite 作为中心数据库。

### 2.2 项目规模

* 每台工控机的交付验收上限为六台 MV-CS020-60GM；

* 上位机必须依据会话和状态上报动态建立拓扑，不得硬编码工控机总数；

* 任何容量参数必须有配置上限，不能形成无界设备、事件、上传、日志或处理任务集合；

* 工控机内部存在的额外逻辑槽位不扩大当前项目硬件验收范围。

## 4. 通信与连接管理

### 4.1 链路职责

* 控制链路使用 WebSocket：心跳、状态、报警、事件触发通知、命令、ACK、命令结果和低帧率预览；

* 数据链路使用 HTTP/REST：会话、事件元数据、上传创建/恢复、分块和 complete；

* 大文件上传不得阻塞心跳、事件广播、报警和相机控制；

* 现有文件上传 REST 路径、SHA-256、`receivedChunks` 和幂等 complete 语义保持与 Uplink v1 一致。

### 4.2 会话和能力协商

| ID           | 优先级 | 需求                                                                 |
| ------------ | --- | ------------------------------------------------------------------ |
| HOST-NET-001 | P0  | 会话必须记录 machineId、productionLineId、软件版本、协议版本、能力集合、连接时间、远端地址和最后心跳时间。 |
| HOST-NET-002 | P0  | 同一 machineId 出现第二个活动会话时必须按明确策略拒绝或替换旧会话并报警，不能同时向两个会话广播控制命令。         |
| HOST-NET-003 | P0  | 未知协议版本必须拒绝；未知可选能力可以忽略，但不能据此启用严格 T0。                                |
| HOST-NET-004 | P0  | 只有双方声明严格 T0 能力时，节点状态才可进入 `COORDINATED`；否则为 `LEGACY`。               |
| HOST-NET-005 | P0  | 连接、断开、替换、协议不兼容和恢复必须写设备日志和审计记录。                                     |

### 4.3 在线状态

上位机根据协商心跳周期和最后成功消息时间维护 `ONLINE`、`UNSTABLE`、`OFFLINE`。具体超时可配置；默认在连续两个周期未收到心跳时进入 `UNSTABLE`，连续六个周期未收到时进入 `OFFLINE`。恢复后自动请求完整状态，不删除历史设备或未完成事件。

## 5. 时间同步与可信度

### 5.1 权威时钟层级

系统按以下顺序识别并展示时钟来源：

1. 外部硬件 PTP Grandmaster；
2. 操作系统 PTP 或 NTP；
3. 相机 ticks 与工控机 UTC 偏移模型；
4. 工控机接收系统时间；
5. 未知。

上位机负责监控、报警和分析可信度，不固定承担 Grandmaster。现场若将上位机配置为 NTP/PTP 服务端，必须作为单独部署方案验证，不能由应用进程隐式完成。

### 5.2 时间字段

每帧索引至少保存：`cameraFrameNumber`、`sequenceNumber`、原始相机 ticks/频率、`receivedUtcNs`、`correctedCaptureUtcNs`、`clockSource`、`clockOffsetNs`、`uncertaintyNs` 和 `syncState`。JSON 纳秒字段使用十进制字符串，数据库使用有符号 64 位整数。

| ID            | 优先级 | 需求                                                                         |
| ------------- | --- | -------------------------------------------------------------------------- |
| HOST-TIME-001 | P0  | 上位机不得用收到网络消息的时间替代帧采集时间或事件 T0。                                              |
| HOST-TIME-002 | P0  | 原始时间、接收时间和校正时间必须同时保留，任何重新校正不得覆盖原始证据。                                       |
| HOST-TIME-003 | P0  | 只有 `SYNCED` 且不确定度满足现场阈值的帧可以标为高可信；其余帧仍可浏览，但必须显示状态和不确定度。                     |
| HOST-TIME-004 | P0  | 上位机必须显示工控机级及相机级时钟源、当前偏移、最大偏移、最后同步时间、Grandmaster（若有）和同步状态。                  |
| HOST-TIME-005 | P0  | Warning/Alarm 阈值和持续时间可配置。初始硬件 PTP 目标为 Warning 1 ms、Alarm 5 ms，最终指标以实机报告为准。 |
| HOST-TIME-006 | P0  | 在没有硬件验证记录时，UI、报表和验收结果不得宣称亚毫秒同步。                                            |

## 6. 工控机和相机管理

### 6.1 工控机

上位机持久化 machineId、名称、生产线、IP、软件版本、协议/能力、在线状态、最后心跳、CPU、内存、数据卷、缓存卷、日志卷、数据库状态、时间状态、相机数量和上传队列摘要。MAC 地址只有工控机明确上报时才保存，不通过跨网段猜测获得。

### 6.2 相机

相机信息包括 cameraId、所属 machineId、名称、SN、型号、IP、安装位置、拍摄方向、描述、启用状态、运行状态、实际 FPS、丢帧、最后帧时间和时间同步质量。上位机以 `(machineId, cameraId)` 作为逻辑唯一键，SN 用于设备核对。

相机运行状态至少映射为 `OFFLINE`、`IDLE`、`ACQUIRING`、`WARNING`、`ERROR`。上位机必须保留工控机返回的稳定业务错误码和可选厂商诊断码，但不能把厂商码作为唯一业务状态。

### 6.3 参数控制

| ID           | 优先级 | 需求                                                                            |
| ------------ | --- | ----------------------------------------------------------------------------- |
| HOST-CAM-001 | P0  | 参数页面首先读取设备 capabilities 和当前实际值，只允许提交设备声明支持的字段和范围。                             |
| HOST-CAM-002 | P0  | 首版必须支持现有适配器已实现的曝光/自动曝光、增益、帧率、ROI、翻转、像素格式、触发模式/源/延迟、GigE 包大小、传输延迟和已证明支持的线路 IO。 |
| HOST-CAM-003 | P0  | 参数更新返回保存值、运行时实际回读值、配置修订和错误原因；失败时 UI 不得假装新值已经生效。                               |
| HOST-CAM-004 | P0  | 启停、连接、断开、抓图和软件触发必须显示命令 ID、执行节点、成功/失败和完成时间。                                    |
| HOST-CAM-005 | P1  | 参数模板只能将共同支持字段下发给目标设备；不支持字段必须在执行前列出，不能部分静默忽略。                                  |

## 7. 实时预览

* 支持单相机、最多四路工控机内宫格和跨工控机自选宫格；

* 支持暂停/恢复、Fit、1:1、缩放、拖动、FPS、帧号、采集时间和时间质量显示；

* 接收现有 Uplink `preview.frame` 二进制格式，单 JPEG 最大 2 MiB，头最大 64 KiB；

* 远程预览是尽力而为的最新帧，不确认、不重传、不作为事故证据；

* 无帧、帧过期、时间不可用或节点掉线必须显示占位和原因，不得继续显示旧图而不标记；

* 上位机应限制同时解码和渲染任务数，所有网络接收和 JPEG 解码不得阻塞 Qt UI 主线程。

## 8. 全局断纸事件协调

### 8.1 全局 ID 和触发通知

触发工控机生成全局唯一 `eventId` 和 T0。上位机收到 `alarm.code=BREAK_EVENT_TRIGGERED` 后，以 `eventId` 幂等登记全局事件。相同 ID、相同核心内容返回现有事件；相同 ID、不同 T0/来源进入冲突状态并产生 Critical 报警。

| ID           | 优先级 | 需求                                                               |
| ------------ | --- | ---------------------------------------------------------------- |
| HOST-EVT-001 | P0  | 事件通知处理、数据库登记和广播调度必须优先于关键帧及原始文件上传。                                |
| HOST-EVT-002 | P0  | 上位机不得重新生成或替换触发工控机给出的 eventId。中心数据库可以使用内部主键，但所有外部关联继续使用原 eventId。 |
| HOST-EVT-003 | P0  | 事件至少保存 T0、触发工控机、触发相机、来源、类型、等级、时间质量、前后窗口和配置修订。                    |
| HOST-EVT-004 | P0  | 触发节点时间降级时仍创建事件，但全局事件必须标为时间可信度下降。                                 |

### 8.2 广播和 ACK

上位机向事件发生时所有在线且声明 `event.lockByUtc` 的同生产线节点广播相同 eventId/T0。命令 body 和 `EventLockAck` 采用[工控机集成新增需求](edge-host-integration-additional-requirements.md)第 5 章的最小契约。

| ID           | 优先级 | 需求                                                                 |
| ------------ | --- | ------------------------------------------------------------------ |
| HOST-EVT-010 | P0  | 自动广播命令按 eventId+machineId 幂等持久化；上位机重启后只重发未确认节点，不生成新事件。             |
| HOST-EVT-011 | P0  | `event.lockByUtc` 是系统自动协调命令，不要求人工确认或强制审计；广播范围限制在同生产线。                 |
| HOST-EVT-012 | P0  | 正常局域网从收到通知到向在线节点完成广播的 P95 目标不超过 100 ms，但事件锁定正确性只能依据 T0，不能依据广播到达时间。 |
| HOST-EVT-013 | P0  | ACK 超时、节点离线、传统节点、同步降级、缓存不足、相机失败和序号缺口必须分别保存，不能合并成一个无原因的失败状态。        |
| HOST-EVT-014 | P0  | 同一节点的重复 ACK 必须幂等；内容冲突进入 `CONFLICT` 并要求人工处置。                        |

### 8.3 全局事件状态

全局协调状态：

```text
TRIGGERED -> BROADCASTING -> LOCKING -> LOCKED_COMPLETE
                                   \-> LOCKED_PARTIAL
                                   \-> LOCK_FAILED
```

数据状态独立维护：

```text
WAITING_UPLOAD -> UPLOADING -> UPLOADED -> PROCESSING -> READY
                         \-> UPLOAD_FAILED
                                      \-> PROCESS_FAILED
```

事件总状态由协调状态、每节点上传状态、完整性和处理状态派生，不得用单一枚举覆盖所有子状态。只要任一预期节点离线、传统模式、ACK 为 PARTIAL/FAILED、文件缺失或时间质量不满足阈值，全局协调结果不得显示 COMPLETE。

## 9. 文件接收、校验与集中存储

### 9.1 接收格式

| ID            | 优先级 | 需求                                                                       |
| ------------- | --- | ------------------------------------------------------------------------ |
| HOST-DATA-001 | P0  | 支持 event manifest v3/PBNVME2 和 manifest v4/PBNVME3；未来高版本必须显式拒绝，不能尝试降级解析。 |
| HOST-DATA-002 | P0  | 每个逻辑文件按 machineId、eventId、logicalFileId、长度和 SHA-256 建立幂等上传对象。            |
| HOST-DATA-003 | P0  | 已接收分块由服务端持久化，重连后返回 `receivedChunks`；重复块内容相同返回成功，不同返回冲突。                  |
| HOST-DATA-004 | P0  | 只有分块完整、长度正确、整文件 SHA-256 正确并完成原子提交后，文件状态才能进入 COMPLETED。                   |
| HOST-DATA-005 | P0  | manifest 文件数、路径、长度、摘要和块内结构校验全部通过后，节点事件贡献才能进入 VERIFIED。                   |

### 9.2 中心目录

建议目录结构：

```text
Data/Events/YYYY/MM/DD/{eventId}/
  global-event.json
  EDGE-001/
    manifest.json
    keyframes/
    raw/
  EDGE-002/
    manifest.json
    keyframes/
    raw/
  processed/
    {processingTaskId}/
```

`global-event.json` 是上位机生成的协调索引，不得冒充工控机原始 manifest。所有后处理、缩略图和导出缓存必须放在 `processed` 或独立缓存目录，不覆盖节点原始文件。

### 9.3 磁盘水位

上位机监控总空间、可用空间、事件目录、临时上传和处理产物。阈值可配置，初始建议 Warning 20%、Alarm 10%、Critical 5%。Critical 时拒绝新的大文件上传并返回明确的空间不足错误，但继续处理控制消息和已有事件状态；不得自动删除未完整、未上传、锁定或禁止删除的证据。

## 10. MySQL 8 数据模型

MySQL 保存结构化元数据，不保存大批原始图像 BLOB。至少包含：

* `ipc_device`：工控机、会话能力、在线和时间状态；

* `camera`：相机静态信息、所属节点和当前状态；

* `camera_config_history`：配置修订、实际回读值、操作者和时间；

* `break_event`：全局事件、T0、触发来源、协调/上传/处理/完整性状态；

* `break_event_node`：每事件每工控机 ACK、实际范围、时间质量和上传状态；

* `break_event_camera`：每事件每节点每相机的帧数、范围、缺口、配置快照和时间质量；

* `event_file`：logicalFileId、路径、长度、SHA-256、上传状态和完整性；

* `frame_index`：事件、节点、相机、帧号、序号、原始/校正时间、块路径、块内偏移和长度；

* `upload_session`/`upload_chunk`：分块事实、重试和完成状态；

* `processing_task`/`processing_result`：算法、版本、配置、进度、异常类型、置信度和区域；

* `alarm_log`、`system_log`、`audit_log`：报警、日志和关键操作审计。

| ID          | 优先级 | 需求                                              |
| ----------- | --- | ----------------------------------------------- |
| HOST-DB-001 | P0  | 数据库迁移必须有版本、事务和失败回滚；高版本数据库不得由旧程序打开写入。            |
| HOST-DB-002 | P0  | 文件系统是原始文件事实源，MySQL 与文件提交无法形成同一事务时必须通过启动/周期对账恢复。 |
| HOST-DB-003 | P0  | 数据库临时不可用时停止产生不可恢复的数据库写入，不删除已接收文件；恢复后执行有界补偿。     |
| HOST-DB-004 | P0  | 常用事件查询在正式容量基线下目标不超过 2 秒，分页必须有最大页大小。             |

## 11. 上传状态与进度

上传状态至少包括 `WAITING`、`UPLOADING`、`RETRYING`、`COMPLETED`、`FAILED`、`MANUAL_INTERVENTION`。暂停只在服务端明确支持时提供，不能仅停止 UI 刷新却显示为 PAUSED。

进度按以下层次计算：

1. 文件：已确认分块字节 / 文件总字节；
2. 相机：该相机文件已确认字节 / 总字节；
3. 工控机：该节点全部事件文件已确认字节 / 总字节；
4. 全局事件：所有预期节点已确认字节 / 已声明总字节。

上位机显示总大小、已接收、剩余、百分比、当前速度、文件/相机/节点、重试次数和最后错误。未收到 manifest、存在传统/离线节点或总字节未知时，应显示“总量未完整”，不能给出虚假的 100%。

## 12. 断纸事件查询与分析工作台

### 12.1 查询

支持按时间范围、eventId、工控机、相机、触发来源、协调状态、上传状态、处理状态、时间质量、完整性和是否异常筛选。列表显示 T0、触发节点/相机、参与节点/相机数、缺失节点、协调结果、上传、处理、完整性、异常帧数和备注。

### 12.2 统一时间游标

分析工作台维护唯一 `GlobalTimeCursorUtcNs`。每个相机根据校正 UTC 时间寻找最近真实帧，不能使用相同 Frame # 对齐。每个画面显示实际帧时间、与游标的 `deltaT`、syncState 和 uncertainty；没有符合搜索窗口的帧时显示 `NO FRAME`。

| ID           | 优先级 | 需求                                                                         |
| ------------ | --- | -------------------------------------------------------------------------- |
| HOST-ANA-001 | P0  | 输入绝对时间、相对 T0 时间或选择任意相机任意帧，都能更新全局时间游标并定位其他相机的最近帧。                           |
| HOST-ANA-002 | P0  | 时间对齐查询必须基于 `correctedCaptureUtcNs`；该字段不可用时可使用接收时间作为降级参考，但必须醒目标记且不得混入高可信统计。 |
| HOST-ANA-003 | P0  | 支持 Master Camera 上一帧/下一帧、鼠标滚轮、键盘快捷键和自选相机联动。                                |
| HOST-ANA-004 | P0  | 支持按时间步长和按 Master Camera 逐帧播放；解码速度不足时允许跳过显示帧，但游标和实际展示帧时间必须一致。               |
| HOST-ANA-005 | P0  | 每相机窗口支持 Fit、1:1、缩放、拖动、像素信息、帧号、时间、异常框显示/隐藏。                                 |

### 12.3 Timeline

Timeline 标记数据起止、T0、当前游标、节点/相机缺口、同步降级区间和异常帧。点击任意位置必须按真实索引定位；缺失数据不得由相邻帧静默填充。

## 13. OpenCV 后处理

* 支持全局默认自动处理开关，以及单事件开始、重新处理和取消；

* 状态为 `NOT_PROCESSED`、`WAITING`、`PROCESSING`、`COMPLETED`、`FAILED`、`CANCELLED`；

* 显示总帧、已处理、当前节点/相机/帧、异常数、速度、耗时和错误；

* 结果至少保存 eventId、machineId、cameraId、frameSequence、算法名称/版本/配置版本、异常类型、置信度、BoundingBox/ROI 和处理时间；

* 新算法重处理必须生成新的 processingTaskId，不能覆盖历史结果；

* 原始块只读，处理图片和索引存入独立目录；

* 第一阶段具体纸病/瑕疵分类和验收数据集必须另行冻结，未冻结前算法结果标记为原型。

## 14. 报警、日志与审计

报警来源包括工控机离线/资源过高、相机离线/采集异常/丢帧、时间失锁/漂移、事件锁定失败、文件缺失/Hash 错误、上传失败、MySQL 异常、磁盘不足和处理失败。

报警支持 raise、重复计数、更新、clear、ack 和历史查询。日志至少分 System、Device、Camera、Time、Network、Event、Upload、Processing、Database、Security，支持时间、级别、machineId、cameraId、eventId、关键字过滤。

相机配置、系统配置、事件复核、重传、数据删除、用户权限和安全设置必须写审计日志，包含操作者/系统主体、时间、目标、旧值摘要、新值摘要、结果和业务错误码。自动 `event.lockByUtc` 广播不列为强制审计项。

## 15. 异常恢复

| ID           | 优先级 | 需求                                                       |
| ------------ | --- | -------------------------------------------------------- |
| HOST-REC-001 | P0  | 工控机掉线不删除设备和事件；恢复后请求完整状态、重发未确认广播并继续已有上传。                  |
| HOST-REC-002 | P0  | 上位机重启后恢复未完成事件协调、上传 checkpoint、处理任务和 PARTIAL/CONFLICT 状态。 |
| HOST-REC-003 | P0  | MySQL 不可用时 UI 保持运行并明确显示只读/降级状态；已提交文件保留，恢复后有界对账。          |
| HOST-REC-004 | P0  | 临时上传目录、正式事件目录和 MySQL 索引在启动时对账；损坏文件隔离且不自动删除证据。            |
| HOST-REC-005 | P0  | 处理进程异常不得改变上传完整性或原始文件；重新处理使用新任务。                          |

## 16. UI 页面

主程序至少包含：Dashboard、工控机管理、相机管理、实时预览、断纸事件、上传状态、断纸分析、后处理任务、报警中心、日志、审计和系统设置。

Dashboard 展示在线工控机/相机、协调能力、PTP/NTP 状态、磁盘、MySQL、当前报警和最近事件。任何统计均显示分母来源；设备清单尚未完整时不能显示虚假的“全部在线”。

网络收发、文件读写、Hash、MySQL、PBNVME 解析、OpenCV、Timeline 大索引和图片解码不得在 Qt UI 主线程执行。后台任务队列必须有容量、取消和确定性关闭路径。

## 17. 安全与权限

角色至少包括：

* **Operator**：查看状态、事件和分析；

* **Engineer**：相机参数、后处理配置、重新处理；

* **Administrator**：系统、工控机、用户、保留和受控删除。

现有 Uplink v1 为明文且无应用鉴权，不提供机密性或对端身份保证；SHA-256 只用于内容完整性校验。本项目接受该风险，不把网络隔离、TLS、认证或安全协议升级列为验收要求。

## 18. 配置、容量与性能

### 18.1 可配置项

监听地址、允许节点、心跳/离线阈值、时间同步阈值、事件前后时长、广播/ACK 超时、上传并发、单节点和总带宽、分块大小、存储路径、水位、预览上限、处理线程、MySQL、日志和数据保留均不得硬编码。

### 18.2 容量模型

正式设计前必须冻结工控机数量、每机相机数、FPS、分辨率、像素格式、单帧大小、前后时长、日事件数、网络带宽、磁盘容量和保留周期。

```text
EventSize ≈ N_camera × FPS × ImageSize × (T_pre + T_post)
DailySize ≈ EventSize × EventPerDay
```

该结果决定上传并发、MySQL frame\_index 方案、磁盘/RAID、处理吞吐和保留周期。上位机必须在启动或配置保存时拒绝超过已批准容量预算的配置，而不是创建无界任务。

### 18.3 性能目标

* 普通设备控制响应目标不超过 2 s；

* 正常局域网事件广播 P95 不超过 100 ms；

* 常用事件查询不超过 2 s；

* UI 普通操作无明显冻结；

* 已索引本地事件支持流畅逐帧浏览；

* 上传限速和并发不能挤占控制消息；

* 亚毫秒时间精度必须由目标硬件报告证明，不作为纯软件默认承诺。

## 20. 验收场景

| 编号    | 场景       | 验收结果                                                         |
| ----- | -------- | ------------------------------------------------------------ |
| AC-01 | 多设备上线    | 正确展示全部已登记工控机、每机最多六台目标相机、能力、在线和时间状态。                          |
| AC-02 | 相机控制     | 启停、参数更新、抓图和预览返回实际结果；不支持参数不可提交。                               |
| AC-03 | 时间源降级    | 模拟 PTP→NTP→接收时钟，状态、偏移、不确定度、报警和帧可信度正确变化。                      |
| AC-04 | 严格 T0    | 任一工控机产生 eventId/T0，其他在线协同节点按同一 T0 锁定并返回 ACK；来源节点重复广播幂等。      |
| AC-05 | 部分节点     | 事件发生时节点离线、传统模式或缓存不足，事件创建成功但为 PARTIAL，并显示每节点原因。               |
| AC-06 | 上传恢复     | 上传中断后依据服务端 `receivedChunks` 续传，不重传已确认块，最终 SHA-256 正确。        |
| AC-07 | 上位机重启    | 恢复未确认广播、未完成上传、处理任务和 PARTIAL/CONFLICT，不生成重复事件。                |
| AC-08 | 格式兼容     | 同时导入 manifest v3/PBNVME2 和 manifest v4/PBNVME3，未知高版本明确拒绝。    |
| AC-09 | 时间定位     | 输入绝对时间或 T0 偏移，所有相机定位最近真实帧并显示 deltaT、syncState 和 uncertainty。 |
| AC-10 | Frame 联动 | 选择任意相机某帧后，其他相机按该帧校正时间更新；无匹配时显示 NO FRAME。                     |
| AC-11 | 上传进度     | 按文件、相机、工控机和全局事件显示服务端事实进度；总量未知时不显示虚假 100%。                    |
| AC-12 | MySQL 异常 | 数据库中断时 UI 不崩溃、文件不删除，恢复后对账并补建索引。                              |
| AC-13 | 磁盘不足     | Critical 时拒绝新大文件但控制链路可用，不自动删除受保护证据。                          |
| AC-14 | 后处理      | 新任务生成独立结果和异常 Timeline，原始块及历史结果保持不变。                          |

## 21. 验收限制

自动化测试必须使用模拟工控机、模拟相机数据和协议回环。PTP 精度、MV-CS020-60GM 时间戳、目标网卡/交换机、生产带宽、目标磁盘、真实上位机服务端和长稳运行必须形成独立实测记录。未执行的硬件或系统集成测试必须明确标记为未验证，不能由单元测试、模拟器或代码审查推断为通过。
