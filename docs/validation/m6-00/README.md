# M6-00 算法验收门禁

## 当前结论

截至 2026-08-04，门禁结论为 **blocked / not-approved**。仓库没有可识别的冻结标注数据集、经业务批准的质量阈值、目标工控机算法性能预算或完整审签记录。因此，后续 M6 接口和传统视觉实现可以作为原型开发，但不得宣称“正式算法已通过验收”。

机器可读结论见 `algorithm-acceptance-baseline-v1.json`。本文档、JSON 模板或 CTest 通过都不代表算法质量验收通过。

## 已固定的规则

- 标签分为 `normal_web`、`web_break`、`non_break_disturbance` 和 `unscorable`，定义见 `labeling-and-evaluation-v1.md`；
- 主要质量指标是事件级召回率、事件级精确率、每相机有效小时误报率和检测延迟；帧级准确率不能替代它们；
- development、validation、test 必须按生产卷、采集会话和真实事件分组隔离，相邻帧不得跨集合；
- 数据集原图可留在受控外部存储，批准 manifest、根摘要和评估报告必须版本化；
- 四路各 60 fps 且不降采样时，算法入口理论负载为 240 frame/s；实际生产 ROI、像素格式、线程数、跳帧政策和资源预算仍需批准；
- 传统视觉代码不需要外部模型时，以算法语义版本、源码提交和配置摘要追踪；任何模型、背景模板或标定制品必须另登记来源、许可证、版本、大小和 SHA-256。

## 解除阻塞所需证据

1. 复制 `dataset-manifest.template.json`，生成符合 `dataset-manifest-v1.schema.json` 的 `frozen` 数据集 manifest，并提供可复核的 SHA-256 根摘要。
2. 由生产/工艺负责人批准断纸业务定义、漏报成本、可接受误报率和最大检测延迟。
3. 由算法与 QA 负责人批准事件匹配窗口、最小样本量、分层覆盖、标注复核和置信区间规则，并保证冻结 test 集未参与调参。
4. 记录目标工控机 CPU/内存、实际 ROI、像素格式、四路帧率、算法线程数；批准平均/P95/P99 单帧耗时、持续吞吐、CPU 和工作集上限。
5. 复制 `gate-review-record.template.md` 完成四方审签；若存在外部制品，同时记录来源、授权、版本、SHA-256 和兼容运行时。
6. 在冻结数据集和目标硬件上生成可复现报告。报告必须包含总体与分层指标、置信区间、失败样本清单、运行命令、算法/配置/数据集摘要和原始机器可读结果。

全部证据齐备后，应更新基线版本并把状态改为 `approved`；不能直接修改历史数据集或把模板改名冒充批准记录。

## 文件说明

| 文件 | 用途 | 是否验收证据 |
| --- | --- | --- |
| `algorithm-acceptance-baseline-v1.json` | 当前门禁状态、已知负载、待批准数值和阻塞项 | 是，当前只证明未批准 |
| `labeling-and-evaluation-v1.md` | 标签、匹配、指标和数据防泄漏规则 | 需审签后才是批准规范 |
| `dataset-manifest-v1.schema.json` | 数据集清单格式 | 否，仅是合同 |
| `dataset-manifest.template.json` | 待填写示例 | 否，固定为 draft |
| `gate-review-record.template.md` | 人工审签和目标机记录模板 | 否，未签字模板不是证据 |

## 数据与安全

不要把生产原图、人员姓名、精确厂址、凭据或未经授权的数据提交到仓库。manifest 使用假名化站点/产线/生产卷标识；原始数据保存在批准的受控位置，仓库只记录逻辑引用和摘要。
