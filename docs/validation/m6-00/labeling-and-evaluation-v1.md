# M6-00 标签与评估规范 v1.0.0

## 状态

本规范是待生产/工艺、算法和数据 QA 负责人审签的候选基线。审签前不得视为正式业务定义。

## 标注单位与类别

数据集至少同时保存“事件”和“帧/时间段”两层标注。事件是质量验收的主要单位；帧标注用于定位首个可见异常、计算检测延迟和诊断失败原因。

| 类别 | 定义 | 指标处理 |
| --- | --- | --- |
| `normal_web` | 纸幅连续且没有经现场证据确认的断纸；允许记录正常纹理和稳定边缘变化 | 负类 |
| `web_break` | 经现场记录或双人复核确认发生纸幅连续性丧失；包含全幅断裂和由边缘起始并继续发展的断裂 | 正类 |
| `non_break_disturbance` | 外观异常但未发生断纸，例如接头、抖动、褶皱、松弛、光照突变、清洁/维护或人员干预 | 必须作为困难负类单独报告 |
| `unscorable` | 画面缺失/损坏、时间无法对齐、关键 ROI 被遮挡，或复核者无法形成结论 | 不进入质量分母，但数量、时长和原因必须报告 |

`web_break` 不能只由算法输出自证。每个正事件至少需要生产记录、外部信号或两名授权复核者的一致结论；不一致时由第三人裁决并保留原始意见。

每个正事件记录：假名化生产卷/会话 ID、相机 ID、最早可见断纸时间/帧、确认依据、可见区域、事件结束时间、标注者和复核状态。对 `non_break_disturbance` 还应记录扰动子类，避免把所有困难负样本折叠为普通正常帧。

## 数据拆分与冻结

- 拆分单位至少是生产卷或连续采集会话；同一真实事件、事件前后窗口和时间相邻帧只能位于一个 split。
- 同一来源文件的裁剪、缩放、增强或重复帧不能跨 development、validation、test。
- development 可用于实现；validation 可用于阈值和候选参数选择；frozen test 只用于最终评估，失败后不得继续在原版本上调参并重复宣称独立验收。
- 数据集版本变化、标签修订、样本增删或摘要变化都必须生成新版本和变更记录。
- 评估需按相机、纸种/克重（若授权）、班次/光照、速度区间和扰动子类分层；无法收集的维度明确记为缺失。

## 事件匹配

预测事件与真实事件采用一对一匹配。匹配窗口的提前容差、延后容差和跨相机合并规则必须在审签记录中填入数值，评估脚本不得自行选择能使结果更好的窗口。

- 一个真实事件最多匹配一个预测事件；匹配成功计为 TP。
- 未匹配真实 `web_break` 计为 FN。
- 未匹配预测事件计为 FP；冷却期间被系统合并的输出仍按批准的合并规则审计。
- 同一真实事件产生多个未合并预测时，除一个 TP 外，其余按 FP 处理，除非批准规则明确证明它们来自独立相机且只在系统层合并。
- `unscorable` 区间内的预测单独报告，不静默计入 TP 或删除。

## 指标定义

```text
eventRecall = TP / (TP + FN)
eventPrecision = TP / (TP + FP)
falseAlarmsPerCameraHour = FP / 有效负类相机运行小时
detectionDelayMs = 首个匹配预测候选时间 - 真实事件最早可见时间
```

- 同时报告分子、分母、点估计和 95% 置信区间；样本量不足时不能只报告百分比。
- 召回率和精确率建议使用二项比例的 Wilson 区间；误报率建议报告 Poisson 率区间及累计有效相机小时。
- 检测延迟至少报告中位数、P95、最大值和负延迟数量；负延迟需人工审查标签时间或预兆定义。
- 帧级混淆矩阵、ROI overlap、面积比例和变化量是诊断指标，不替代事件指标。
- 所有结果同时给出总体值和上述分层值；任何批准的硬门槛应同时说明是作用于总体、每层还是置信区间下界/上界。

## 性能评估

固定并记录以下条件：目标机 CPU/内存、Windows 版本、电源模式、算法线程数、相机数、ROI、像素格式、步幅、帧率、编译配置、OpenCV/运行时版本、算法版本和配置 SHA-256。

四路各 60 fps 且每帧进入算法时，持续入口为 240 frame/s；单工作线程的理论平均服务时间上限是约 4.1667 ms/frame。该算术只是队列不持续增长的必要条件，不是已批准性能指标。多工作线程、保序开销、P95/P99 延迟、CPU、工作集、热稳定和跳帧上限必须在目标机实测并审签。

性能报告至少包含：预热时长、正式测量时长、输入/处理/跳过帧数、队列高水位、平均/P50/P95/P99/最大算法耗时、持续吞吐、进程/算法 CPU、工作集、异常数和系统是否降频。测量期间不得用未批准的降采样掩盖吞吐不足。

## 可复现报告最小内容

- 数据集 ID、版本、manifest SHA-256 和 split 摘要；
- 算法语义版本、源码提交、构建配置、算法配置 SHA-256；
- 外部制品的来源、授权、版本、大小、SHA-256 和运行时；
- 完整评估命令、随机种子（若有）、事件匹配参数和工具版本；
- 质量与性能的机器可读原始结果、分层汇总、置信区间和失败样本逻辑 ID；
- 运行环境清单、开始/结束 UTC、执行人和审查人；
- 明确的 passed/failed/not-executed 判定，不允许只保留成功截图。
